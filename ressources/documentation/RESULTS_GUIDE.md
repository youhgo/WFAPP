## Results Location

Once APP finishes processing an archive, results are stored in the shared volume configured during installation. By default, it follows this path structure:

```bash
Your_Share_Folder/
├── depot/           # Raw forensic archives uploaded via the API or Web GUI
└── work/            # Parsed artifacts and execution logs
    ├── execution_logs/ # Processing logs from the orchestrator
    └── <casename>/     # Results grouped under the specified Case Name
        ├── WorkStation_DESKTOP-9I162HO_2026-09-08T23-45-46/
        └── DomainController_FOREST_2026-09-16T05-47-18/
```

Inside the Case Name folder, each processed machine has its own directory containing parsed outputs.

## Parsed Machine Directory Structure

Each machine directory contains categorized outputs organized into logical subfolders:

```bash
DomainController_FOREST_2026-08-18T04:16:47/
├── parsed/
│   ├── debug/              # Execution logs of DFIR-ORC and individual parsers
│   ├── events/             # Normalized EVTX event logs in JSON format
│   ├── hives/              # Extracted Registry hives parsed via regipy and YARP
│   ├── lnk/                # Parsed Windows LNK (shortcut) files
│   ├── mft/                # Master File Table (MFT) and USN Journal outputs
│   ├── network/            # Network activity summaries (Netstat, TCP connections)
│   ├── powershell/         # PowerShell command history and script block logs
│   ├── prefetch/           # Application execution evidence from Prefetch files
│   ├── process/            # Process execution context (Autoruns, parent-child trees)
│   ├── SRUM/               # System Resource Usage Monitor database tables
│   ├── textLogs/           # Plain text application and system logs
│   ├── timeline/           # Full Plaso timeline (JSON and CSV formats)
│   └── parsed_for_human/   # Standardized, simplified CSVs for rapid triage
```

> [!NOTE]
> The pipeline also executes MaximumPlasoParser to normalize and filter Plaso timelines. 
> For more information, visit the [MaximumPlasoParser Repository](https://github.com/youhgo/maximumPlasoTimelineParser).

## Standardized Triage (parsed_for_human)

The `parsed_for_human` folder is the primary workspace for investigators. It aggregates critical forensic artifacts into flat, easy-to-read CSV files using a consistent layout (`DATE|TIME|ID|...`).

> [!IMPORTANT]
> The CSV formats in `parsed_for_human` prioritize clarity and speed of analysis. Because registry hives (like SAM, SOFTWARE) have complex nested structures, they are exported as JSON Lines (`.jsonl`) instead of CSV to prevent data loss. Only the Amcache registry is parsed directly into CSV.

## Investigation Workflows

Using tools like `ripgrep` (rg) in the `parsed_for_human` directory allows you to perform fast, multi-file queries to reconstruct malicious activity.

### Example: Searching for Lateral Movement and Persistence

To search for events within a specific time window across multiple triage files:

```bash
rg -i "2026-01-07\|03:(3|4|5)" \
  user_logon_id4624.csv \
  new_service_id7045.csv \
  Amcache.hve_regpy.csv \
  powershell.csv \
  windefender.csv
```

**Example Output:**

```text
windefender.csv:
2026-01-07|03:32:30|1116 - Detection|VirTool:Win32/MSFPsExecCommand|Severe|NT AUTHORITY\SYSTEM|...|CmdLine:_C:\Windows\System32\cmd.exe ...

windefender.csv:
2026-01-07|03:35:44|1116 - Detection|HackTool:Win64/Mikatz!dha|High|BROCELIANDE\arthur|C:\Users\Public\mimikatz.exe|...

Amcache.hve_regpy.csv:
2026-01-07|03:39:31|beacon.exe|C:\Users\Public\beacon.exe|...

powershell.csv:
2026-01-07|03:37:03|600|powershell Set-MpPreference -DisableRealtimeMonitoring $true; ...
```

## Conclusion

By standardizing and correlating outputs into flat CSV files, APP allows you to transition from raw forensic artifacts to actionable security intelligence in minutes. Prioritize the `parsed_for_human` folder for initial triage and pivot to the full `timeline/` or `hives/` directories for deeper verification.
