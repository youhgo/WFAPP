# How A.P.P Works ⚙️

The **Artefact Parser Project (A.P.P)** is designed to be accessed in two distinct ways:
1. **Via the Web GUI**, for intuitive and manual use.
2. **Via the REST API**, for automation and integration into complex pipelines.

---

## 1️⃣ Using the Web GUI

The Web GUI is the easiest way to interact with APP.

**Default access:**
🔗 `https://wapp.localhost/login_page`

**Default credentials:**
* **Username:** `wapp`
* **Password:** `changeme`

### The Interface Tabs

Once logged in, the interface is divided into 5 main sections:

1. **File Uploader:**
   This is the main interface. It allows you to upload a collection archive (e.g., generated by DFIR-ORC or UAC).
   * On the right side of the screen, you can select/deselect the parsers (analysis modules) you want to execute (Evtx, MFT, Registry, etc.).
   * When sending the archive, a **Task ID** will be provided. It is essential for tracking the progress of the analysis.

2. **Log Viewer:**
   By entering a Task ID, this tab allows you to view execution logs in real-time. It is very useful for checking if a parser has failed or understanding the analysis progress.

3. **Task Status:**
   This tab gives you an overall status (Pending, Running, Finished, Failed) for a given Task ID.

4. **Running Tasks:**
   Displays all tasks currently being processed by the workers. You also have the option to manually stop a task if necessary.

5. **Download DFIR-ORC:**
   Allows you to download a pre-configured `DFIR-Orc.exe` collector, ready to be deployed on a workstation to be investigated with an optimized configuration.

## 2️⃣ Using the REST API (For Automation)

If you are processing many machines or want to script your investigations, the API is the recommended method.

### Parsing an Archive via the API

**Endpoint:** `POST /api/parse/parse_archive`

**Required parameters:**
* `file`: The archive file to analyze.
* `json`: A JSON string containing information about the case (Case Name) and the machine (Machine Name).

**Authentication Example (Session Cookie Retrieval):**
```bash
curl -k -X POST \
-H "Content-Type: application/json" \
-d '{"username": "wapp", "password": "changeme"}' \
-c cookie_jar.txt \
https://wapp.localhost/api/login
```

**Parsing Request Example with Custom Configuration:**
```bash
curl -b cookie_jar.txt -X POST -k https://wapp.localhost/api/parse/parse_archive \
  -F file=@"/path/to/your/archive.7z" \
  -F json='{
    "caseName": "HR_Investigation", 
    "machineName": "Workstation_01", 
    "archiveType": "ORC",
    "parser_config": {
        "evtx": 1,
        "mft": 1,
        "hive": 1
    }
  }'
```

**Expected Response:**
```json
{
  "message": "Your archive has been send to queue",
  "taskId": "b16b2be6-0c04-4540-96e9-ab922c27b2f7",
  "statusUrl": "/api/get_task_status/b16b2be6-0c04-4540-96e9-ab922c27b2f7",
  "runLogUrl": "/api/running_log/b16b2be6-0c04-4540-96e9-ab922c27b2f7"
}
```

## 3️⃣ What Happens During Parsing?

The parsing process (orchestrated by Celery and Redis) follows these key steps:
1. **Extraction:** The archive (ZIP, 7Z...) is extracted to the configured working directory (`SHARED_FOLDER_PATH`).
2. **Dispatching:** Depending on your configuration, various tools are called to process the raw files. For example, EvtxDump for event logs, AnalyzeMFT for the file system, Regipy for the registry.
3. **Formatting & Aggregation:** The raw results are standardized and grouped into a specialized folder called `parsed_for_human/`. These CSV files are identically structured (`DATE|TIME|ID|Information...`) to facilitate correlation (e.g., via Unix commands like `grep` or `awk`, or directly in a SIEM).
4. **Export (Optional):** If configured in your `.env`, the parsed logs are directly pushed to your SIEM (Elasticsearch, Wazuh, Splunk...).

## 4️⃣ Exploring the Results

All results are saved in the shared volume (defined by `SHARED_FOLDER_PATH`).
The typical tree structure looks like this:

```text
📁 shared_results/
 ├── 📁 depot/          # Temporary raw archives
 └── 📁 work/           # Analysis results
     └── 📁 HR_Investigation/   # (Your 'caseName')
         └── 📁 Workstation_01_2026-08-14T.../ # (Your 'machineName' + Timestamp)
             ├── 📁 events/     # Raw EVTX events in JSON
             ├── 📁 hives/      # Extracted registry hives
             ├── 📁 mft/        # Master File Table analysis
             └── 📁 parsed_for_human/  # ❤️ MAIN FOLDER (Readable CSV Results)
```

**The key folder is `parsed_for_human/`.**
It contains "ready-to-use" CSV files like `user_logon_id4624.csv`, `windefender.csv` or `powershell.csv`, allowing you to start your investigation immediately without worrying about converting proprietary Microsoft formats.
